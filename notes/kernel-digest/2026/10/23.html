[$] The end of __get_user() and __put_user() ​

学习价值：展示了内核 API 演进和废弃接口清理的真实过程，是理解 user-space 内存访问接口历史的绝佳案例。

学习价值：内核态 shadow stack 是前沿的内核加固方向，涉及 CET 硬件特性与内核调用栈管理，对学习内核安全机制很有价值。

[PATCH v2 00/16] Move notrace from inline to __always_inline ​

Song Liu (song@kernel.org)｜lkml｜其他动态

该补丁系列（共 16 个 patch）将 notrace 语义从 inline 迁移到 __always_inline。自 commit 45959ee7aa64 起，所有标记 inline 的函数同时隐含 notrace，导致编译器生成的非内联副本无法被 ftrace 追踪、无法作为 BPF fentry/fexit 目标、也无法被 livepatch。本系列先显式标记依赖此隐式行为的函数为 notrace，再移除 inline 的 notrace 含义，使这些副本变为可追踪。

[PATCH] mm/vmalloc: reject overflowing vm_map_ram page counts ​

Shubhang Kaushik (Ampere) (sh@gentwo.org)｜linux-mm

该补丁修复 vm_map_ram() 中的整数溢出问题：它将 unsigned int 页数转换为 unsigned long 字节数时未检查溢出。在 32 位内核上，页数超过 ULONG_MAX >> PAGE_SHIFT 会导致字节数回绕，使 alloc_vmap_area() 和 vmap_pages_range() 只分配回绕后的小映射却对原始大请求返回成功。补丁改为拒绝字节数无法表示的页数。

学习价值：一个典型的内核 API 输入验证漏洞案例，展示了 vmalloc 子系统中页数到字节数转换的溢出风险。

[PATCH RFC v2 37/50] KVM: guest_memfd: Clamp hole punch range to inode size ​

本补丁将 guest_memfd 的 hole punch 范围钳制到 inode 大小。VFS 的 fallocate 只校验 offset 和 length 不超过超级块最大文件大小，允许超出 inode 末尾的范围；folio mode 下截断超出部分是快速 no-op，但 PFN mode 下会不必要地遍历 provider 范围。因此将范围 clamp 到 inode 大小并在起始偏移超出文件末尾时提前返回。

[PATCH net] net: bgmac: fix oversized RX frame check ​

Rosen Penev (rosenp@gmail.com)｜netdev

修复 bgmac 驱动 RX 帧长度检查过宽的问题。原检查将 RX header 中的长度与 BGMAC_RX_ALLOC_SIZE（整个 fragment 大小，含 skb_shared_info 保留空间）比较，而硬件可用的数据区仅为 BGMAC_RX_BUF_SIZE，有效帧最大为 BGMAC_RX_MAX_FRAME_SIZE。介于两者之间的损坏长度会通过检查，导致 skb_put() 越界触发 skb_over_panic。修复为与 BGMAC_RX_MAX_FRAME_SIZE 比较。

[PATCH v2 09/16] arm64: Mark the preempt count helpers notrace ​

Song Liu (song@kernel.org)｜lkml

补丁将 arm64 上的 preempt count 辅助函数（__preempt_count_add/sub、should_resched、preempt_count_set 等）显式标记为 notrace，因为 ftrace_test_recursion_trylock() 在递归检查生效前会读取 preempt_count()，若这些普通 inline 函数被编译器展开为 out-of-line 副本并被追踪将导致递归。x86 和通用版本已是 __always_inline。

学习价值：展示了 arm64 与 x86 在抢占计数实现上的差异，以及 notrace 标注对 tracing 正确性的重要性。

[PATCH v2 06/16] u64_stats: Mark the update helpers used by BPF notrace ​

Song Liu (song@kernel.org)｜lkml

该补丁将 u64_stats 更新辅助函数（u64_stats_update_begin_irqsave()、u64_stats_inc()、u64_stats_add() 等）显式标记为 notrace。原因是 bpf_prog_inc_misses_counter() 和 BPF trampoline 中的 __update_prog_stats() 调用这些函数，若它们可被 fentry 程序挂载会导致无限递归。目前这些函数不被追踪仅是因为 inline 隐含 notrace，显式标记后语义更可靠。

学习价值：帮助学习者理解 BPF fentry 挂载点的递归风险，以及 inline 隐含 notrace 这一微妙依赖关系。

[PATCH v2 05/16] bpf: Mark the bpf_mem_alloc fast path helpers notrace ​

Song Liu (song@kernel.org)｜lkml

该补丁将 bpf_mem_alloc 快速路径辅助函数 unit_alloc()、unit_free()、unit_free_rcu() 所调用的 local_inc_return()、local_dec()、__llist_add()、llist_add() 等内联函数显式标记为 notrace。目的是防止 BPF 程序挂载到这些函数上破坏 per-CPU free list 的一致性。这是将 notrace 从 inline 迁移到 __always_inline 系列补丁的一部分。

学习价值：展示了 bpf_mem_alloc 分配器的内部实现细节，以及 notrace 标记对保护关键数据结构的重要性。

[PATCH v2 04/16] bpf: Mark the BPF trampoline helpers notrace ​

Song Liu (song@kernel.org)｜lkml

该补丁将 BPF trampoline 调用的辅助函数（__bpf_prog_enter*()、__bpf_prog_exit*()、__bpf_tramp_enter/exit()）显式标记为 notrace。若这些函数调用的代码可运行 BPF 程序，挂载程序将导致无界递归，且 __bpf_prog_enter_recur() 的递归检查无法阻止这种情况。同时 migrate_disable()/migrate_enable() 的非内联副本已被 btf_id_deny 拒绝挂载。

学习价值：深入讲解 BPF trampoline 的执行流程和递归防护机制，是理解 fentry/fexit 实现的优质材料。

[PATCH v2 03/16] bpf: Mark bpf_spin_lock helpers notrace ​

Song Liu (song@kernel.org)｜lkml

该补丁将 bpf_spin_lock()/bpf_spin_unlock() 调用的静态内联辅助函数（__bpf_spin_lock_irqsave()、__bpf_spin_unlock_irqrestore()、queued_spin_unlock() 等）显式标记为 notrace。这是延续 commit 178c54666f9c 的工作，防止 fentry 程序挂载后与锁操作形成死锁。queued_spin_unlock() 在 x86 上是普通 inline 函数，需要显式标记保证其非内联副本不可被追踪。

学习价值：结合 bpf_spin_lock 死锁场景讲解 notrace 的必要性，有助于理解 BPF 与锁子系统的交互约束。

[PATCH v2 02/16] x86: Mark CPU state helpers used by resume and kexec notrace ​

Song Liu (song@kernel.org)｜lkml

该补丁将 x86 恢复和 kexec 路径上调用的 CPU 状态辅助函数（wrmsrq()、__write_cr4()、write_cr3()、write_cr0()、load_idt()、loadsegment()、load_gs_index() 等）显式标记为 notrace。原因是 __restore_processor_state() 在 %gs 和 IDT 恢复之前运行，此时函数追踪器尚不能工作；machine_kexec() 在 load_segments() 重置 %gs 后调用 virt_to_phys() 也处于类似状态。

学习价值：揭示了 x86 挂起恢复和 kexec 路径中追踪器不可用的底层原因，是学习 CPU 状态恢复流程的好素材。

[PATCH v2 01/16] x86/paravirt: Mark native pv_ops helpers notrace ​

Song Liu (song@kernel.org)｜lkml

该补丁将 x86/paravirt 中多个 pv_ops 原生实现的静态内联辅助函数显式标记为 notrace。在 CONFIG_PARAVIRT_XXL 下，pv_ops 存储这些函数地址，编译器会生成非内联副本，目前它们不被追踪仅因 inline 隐含 notrace。部分调用方（如 restore_processor_state()、__switch_to()）必须在特定时机禁止追踪，因此需要显式标记以消除对隐式行为的依赖。

学习价值：讲解 paravirt 机制中函数指针与追踪的交互，有助于理解 pv_ops 架构和 ftrace 的约束。

[PATCH v2 00/16] Move notrace from inline to __always_inline ​

Song Liu (song@kernel.org)｜lkml

该补丁系列（共 16 个 patch）将 notrace 语义从 inline 迁移到 __always_inline。自 commit 45959ee7aa64 起，所有标记 inline 的函数同时隐含 notrace，导致编译器生成的非内联副本无法被 ftrace 追踪、无法作为 BPF fentry/fexit 目标、也无法被 livepatch。本系列先显式标记依赖此隐式行为的函数为 notrace，再移除 inline 的 notrace 含义，使这些副本变为可追踪。

学习价值：系统性地展示了 ftrace、BPF trampoline 与 livepatch 共享的函数追踪基础设施，是理解内核可追踪性演进的极佳案例。
