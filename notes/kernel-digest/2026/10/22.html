Linus Torvalds Eliminates Unsafe __get_user() & __put_user() Functions In Linux 7.4 ​

Michael Larabel｜phoronix｜其他动态

Linus Torvalds 在 Linux 7.4 中移除了历史上不安全的 __get_user() 和 __put_user() 内核函数。这些函数缺少 access_ok() 地址校验，容易被误用导致安全问题。此次清理是 Linus 近期亲自提交补丁（部分借助 Claude Code 辅助）的延续。

学习价值：展示了内核 API 安全演进的典型案例，学习者可借此理解 user space 内存访问接口的安全边界与历史包袱清理过程。

[PATCH v1 2/2] mm: multi-gen LRU: remove get_lruvec() ​

Siddharth Chintamaneni (sidchintamaneni@gmail.com)｜linux-mm

该补丁移除 multi-gen LRU 中的 get_lruvec() 辅助函数。该函数最初为防护未初始化 NUMA 节点的 NULL NODE_DATA() 而引入，但在相关 NULL 检查被移除后，它已退化为 mem_cgroup_lruvec() 的薄封装。补丁在所有调用点直接改用 mem_cgroup_lruvec()。

学习价值：典型的内核代码清理案例，可学习如何识别并消除冗余的间接层，以及理解 lruvec 与 memcg 的关系。

[PATCH v1 1/2] mm: multi-gen LRU: use mem_cgroup_lruvec() in get_lruvec() ​

Siddharth Chintamaneni (sidchintamaneni@gmail.com)｜linux-mm

该补丁让 get_lruvec() 直接委托给 mem_cgroup_lruvec()，与 Andrew Morton 指出的 lru_gen_shrink_node() 模式保持一致。此前在命令行禁用 memcg（cgroup_disable=memory）时会直接返回 &pgdat->__lruvec，绕过 lruvec->pgdat 的初始化；但由于所有调用点都在 kswapd_init() 之后运行，实际不构成运行时 bug。

学习价值：展示了内核代码中潜在初始化顺序问题的分析过程，对理解 memcg 与 lruvec 初始化时序很有价值。

[PATCH v3 4/4] mm: pass the number of PTEs to move_pte() ​

Imre Kaloz (kaloz@kernel.org)｜linux-mm

自 commit f822a9a81a31 引入 mremap() 的 PTE 批量优化后，move_ptes() 一次搬移一批 PTE，但只以首个 PTE 调用 move_pte()。sparc64 是唯一重写 move_pte() 的架构，会在 PTE 颜色变化时刷新 D-cache，因此批内其他页面可能残留旧颜色的 cache line。该补丁将 nr_ptes 传递给 move_pte() 以修复此问题。

学习价值：深入展示了 PTE 批量化优化与架构相关 cache 一致性（VIPT D-cache 颜色问题）之间的微妙交互，是学习跨架构内核代码的优质案例。

[PATCH v3 3/4] sparc64: flush vmalloc ranges from the D-cache on map and unmap ​

Imre Kaloz (kaloz@kernel.org)｜linux-mm

sparc64 的 Spitfire/Cheetah L1 D-cache 以 VA bit 13 索引，但 flush_cache_vmap()/flush_cache_vunmap() 是空操作，导致 vmalloc 地址加载的 cache line 在 unmap 后残留，可能读到过期数据，在 UltraSPARC III 上会损坏 BPF 程序和模块数据。补丁在 map/unmap 时逐页在所有 CPU 上刷新，或当范围超过 cache 大小时通过跨 CPU 调用整体刷新 D-cache。

学习价值：罕见的 sparc64 cache 一致性修复案例，深入讲解了虚拟索引 cache 的别名问题及跨 CPU TLB/cache 刷新机制，对理解架构级内存一致性极有价值。

[PATCH v3 2/4] sparc64: flush only the aliased page, not its whole folio ​

Imre Kaloz (kaloz@kernel.org)｜linux-mm

该补丁修正 sparc64 在转换为 folio 后引入的过度刷新问题：move_pte() 与 tlb_batch_add() 每处理一个 PTE 就刷新整个 folio 内所有页的 D-cache，导致大 folio 映射区间中每页被重复刷新多次。在 SMP 上，Spitfire/Cheetah 每次页刷新都是一次向所有在线 CPU 的 cross-call，开销巨大。补丁改为只刷新该 PTE 实际映射的那一页，并把 flush_dcache_folio_all() 还原为 flush_dcache_page_all()。

学习价值：展示了 folio 转换中容易忽略的“按 PTE 调用 vs 按页刷新”语义差异，以及 D-cache alias 与 cross-call 成本的实际影响。

[PATCH v3 1/4] sparc64: skip the trap block in xcall_deliver() when there is no target ​

Imre Kaloz (kaloz@kernel.org)｜linux-mm

xcall_deliver() 在尚未确认目标 CPU 掩码前就通过 trap block 的物理地址写入 mondo 数据与目标列表，而这些地址在 init_IRQ() 初始化前为 0，早期 cross call 会写到物理地址 0。补丁在掩码中没有其他在线 CPU 时提前返回，避免触碰 trap block。

学习价值：典型的早期启动阶段初始化顺序陷阱，说明 SMP cross-call 路径在只有 boot CPU 在线时的边界条件。

[PATCH v3 0/4] sparc64: D-cache alias flushing fixes ​

Imre Kaloz (kaloz@kernel.org)｜linux-mm

这是 sparc64 D-cache alias 刷新修复系列的 cover letter，针对具有 virtually indexed L1 D-cache 的 Spitfire 与 Cheetah。系列包含：xcall_deliver() 无目标时提前返回、只刷新 PTE 映射的单页而非整个 folio（在 Sun Fire V240 上把大 folio 的 colour-changing mremap() 从 7.3 秒降下来）、以及实现此前为空操作的 flush_cache_vmap()/flush_cache_vunmap()。

学习价值：适合了解 VIPT cache alias 问题、架构相关 cache 维护接口与 folio 化带来的性能回归排查思路。

[PATCH net v3] tipc: fix refcount panic in tipc_rcv() when receiving shared skb ​

Tung Nguyen (tung.quang.nguyen@est.tech)｜netdev

TIPC 假设收到的 skb 不与其它使用者共享，但 syzbot 报告收到 shared skb 时在 tipc_rcv() 路径触发 refcount panic，栈显示 pskb_expand_head()/__pskb_pull_tail()/skb_cow_data() 经 tipc_aead_decrypt() 被调用。根因是本地投递 hook 使 skb 被共享，而 TIPC 未做 skb 拷贝/展开保护。

学习价值：有助于理解 skb 共享语义、skb_cow_data() 的作用以及网络协议栈中 refcount 类崩溃的定位方法。

学习价值：有助于了解内核加密子系统的架构分层（lib/crypto vs crypto API）以及不同架构上 AES 硬件指令优化的实现方式。

PHP Updates Released For Two Critical Code Execution Vulnerabilities ​

Michael Larabel｜phoronix

PHP 发布 8.5.12、8.4.27、8.3.36 和 8.2.35 版本，修复两个可导致未认证远程代码执行的关键漏洞。服务器管理员被建议立即更新。该漏洞与 Linux 内核无关。

学习价值：属于用户态软件安全公告，对内核学习者价值有限，仅可作为系统安全意识参考。
