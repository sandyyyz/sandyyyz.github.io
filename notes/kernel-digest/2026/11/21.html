766458ca1197 · GnuPG's GPGME Affected By Critical Security Bug In Turn Affecting Mail Clients, Flatpak ​

Michael Larabel｜phoronix｜其他动态

Werner Koch 宣布 GnuPG 的 GPGME 库存在一个 critical 安全漏洞。该漏洞影响大多数邮件客户端、多数 XMPP 客户端、Flatpak、Samba 等依赖 GPGME 的软件。

学习价值：用户态加密库的安全事件，提醒学习者关注内核之外的供应链安全面。

9ae505c031bc · [PATCH net] ice: do not report CHECKSUM_COMPLETE when an XDP program is attached ​

Tianyi Gao (tianyi@cloudflare.com)｜netdev｜网络

Cloudflare 工程师修复 ice 驱动在 E830 网卡上的问题：当 XDP 程序修改数据包并返回 XDP_PASS 后，硬件计算的 generic checksum（GCS）不再匹配，导致 netdev_rx_csum_fault() 频繁触发。修复方案是在 RX ring 挂载 XDP 程序时不使用 GCS 报告 CHECKSUM_COMPLETE，与 mlx5 的既有做法保持一致。

学习价值：真实生产环境中 XDP 与硬件 checksum 卸载交互的经典案例，展示了 XDP 程序修改报文对协议栈校验和假设的影响。

6a656cb76a4a · [PATCH v2] rust: bindgen: Preserve sched_statistics alignment ​

Peder Bergan via B4 Relay (devnull+peder.bergan.gmail.com@kernel.org)｜rust-for-linux｜Rust in Linux

修复 bindgen 生成的 struct sched_statistics 对齐问题：当 CONFIG_SCHEDSTATS 关闭时该结构体为空但仍保持 cache-line 对齐，而 bindgen 会忽略空类型的对齐，导致 task_struct 中后续字段错位，arm64 上 Rust Binder 通过 CurrentTask::mm() 读到错误指针而拒绝 mmap()。解决方案是将 sched_statistics 声明为 opaque 类型，使 bindgen 使用 C 侧的大小和对齐信息。

学习价值：极佳的案例，说明 C 与 Rust ABI 交互中结构体对齐/padding 的陷阱，以及 opaque 类型在 bindgen 中的重要作用。

827ba10c2f54 · AMDXDNA Driver Reaches Version 1.0, Ryzen AI NPU10 & NPU11 Coming To Linux 7.5 ​

Michael Larabel｜phoronix｜其他动态

AMD 的 AMDXDNA 加速器驱动（用于支持 Ryzen AI NPU）将在 Linux 7.5 内核中宣布达到 1.0 版本，标志着该驱动趋于成熟稳定。同时，新一代 NPU10 和 NPU11 硬件的支持也在推进中。

学习价值：展示了内核加速器驱动从开发到稳定（1.0）的演进过程，适合了解 NPU 驱动子系统的成熟路径。

b3fd41928162 · Intel Preps Linux 7.5 Change To Better Handle Multiple GPUs With Lots Of VRAM ​

Michael Larabel｜phoronix｜其他动态

学习价值：涉及 DRM 子系统中 GEM/TTM 内存管理机制，是了解 GPU 显存地址空间管理的实用素材。

e902463a09aa · [PATCH v6 12/12] rust: xarray: document Guard lock drop semantics ​

Andreas Hindborg (a.hindborg@kernel.org)｜rust-for-linux

为 Rust XArray 绑定的 Guard 补充文档，说明 Guard::store 调用 __xa_store 时，若使用阻塞分配标志会临时释放 xarray 锁进行内存分配后再重新获取。这与 Rust 中 guard 应在整个生命周期内提供持续互斥的惯例不符，跨阻塞 store 的 check-then-act 序列并非原子操作，文档建议使用预分配内存的 entry API 来避免锁释放。

学习价值：深刻揭示了 Rust 锁 guard 语义与 C 内核 API 内部行为（锁释放重获取）的语义冲突，是理解 Rust 内核抽象安全契约的优质素材。

cf23baea5ebd · [PATCH v6 07/12] rust: xarray: add entry API ​

Andreas Hindborg (a.hindborg@kernel.org)｜rust-for-linux

为 Rust XArray 绑定新增 Entry API，模仿 Rust 标准库 HashMap 的 entry 模式，Guard::entry 返回 Vacant 或 Occupied 状态，支持高效的条件插入与修改。该 API 的设计动机来自 Rust null block driver 的内存后端实现需求。

学习价值：展示了如何将 Rust 标准库惯用 API 模式移植到内核数据结构绑定上，是学习内核 Rust API 设计的范例。

3b3829432031 · [PATCH v6 01/12] rust: xarray: minor formatting fixes ​

Andreas Hindborg (a.hindborg@kernel.org)｜rust-for-linux

对 rust xarray 模块进行格式清理以符合内核编码规范：use 语句改为每行一个导入的垂直布局、添加尾部空注释防止 rustfmt 折叠导入、将内核 crate 引用从 crate 改为 kernel、拆分过长的 assert_eq! 语句等。

学习价值：虽是格式修补，但可了解 Rust 内核代码的编码规范细节及与 rustfmt 工具的博弈技巧。

6fe875d3a767 · [PATCH v6 04/12] rust: xarray: add XArrayState ​

Andreas Hindborg (a.hindborg@kernel.org)｜rust-for-linux

为 Rust XArray 绑定新增内部状态结构 XArrayState，封装 C 侧的 xa_state 并持有 Guard 引用以保证独占访问。通过 Deref bound 泛型化 guard 借用，可持有共享或可变引用；Guard::load 改用 xas_load 替代 xa_load，避免后者内部不必要的 RCU 加锁。

学习价值：深入展示了如何将 C 内核的 xas_* 状态机 API 封装为类型安全的 Rust 抽象，并优化掉冗余的 RCU 锁获取。

1fc120e674e2 · [PATCH v6 06/12] rust: xarray: add find_next and find_next_mut ​

Andreas Hindborg (a.hindborg@kernel.org)｜rust-for-linux

本补丁为 Rust 的 XArray 抽象层新增 find_next 和 find_next_mut 方法，用于从指定 index 开始查找下一个元素，并返回元素所在 index 与引用。实现基于 XArray state API 的 xas_find，由于 Guard 已持有 exclusive lock，因此无需再获取 RCU lock。

学习价值：通过这个补丁可以学习如何在 Rust 中封装 C 内核的 XArray state API，以及理解 RCU 与锁的交互关系，是 Rust in Linux 抽象层设计的良好范例。
