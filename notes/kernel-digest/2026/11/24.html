0f48e6f5dea1 · [PATCH net v7 6/9] ipv6: don't send redirects for decrypted skbs ​

Todd Freed (toddfreed@meta.com)｜lkml｜网络

修复 IPv6 转发路径上的明文泄露：当 ip6_forward() 将包从进入的接口转发回去时，会通过 ndisc_send_redirect() 发送 NDISC Redirect，其 Redirected Header 选项会引用原包内容。若设备已解密该包（skb->decrypted 置位），redirect 会把明文片段发回网络，因此对已解密的 skb 不再发送 redirect。IPv4 的 redirect 走 __icmp_send() 已被前序补丁覆盖。

学习价值：展示了加密流量与 ICMPv6 redirect 的交互泄露问题，对理解 skb->decrypted 标志和 ndisc 实现很有帮助。

032ef42c1a39 · [RFC PATCH] mm: memcontrol: let a cgroup opt out of HugeTLB accounting ​

Harshal Patil (harpatil@redhat.com)｜linux-mm｜内存管理

该 RFC 提议允许单个 cgroup 选择退出 HugeTLB 记账。当前 memory_hugetlb_accounting 挂载选项是全局的，对所有 cgroup 生效或都不生效，这对 Kubernetes 等将 huge pages 作为独立资源（hugetlb.<size>.max）管理的场景造成问题，pod 的 HugeTLB 预算会被 memory.max 重复限制。

7008bcfb6f4d · [RFC PATCH 0/3] rust: dma: require device configuration before DMA ​

Matteo Kloiber (kernel@matt3o12.de)｜rust-for-linux｜Rust in Linux

该 RFC 源自关于 max_seg_size 的讨论，实现了通过 InitTokens 传递给 probe() 的 DMA setup token 机制。驱动必须先调用 configure() 消耗 token 并设置 dma::Params（如 streaming_mask、coherent_mask、max_seg_size），才能获得可复制的 dma::Handle 并进行 Coherent 分配或映射。这从类型系统层面强制驱动在 DMA 操作前正确完成设备配置。

学习价值：展示了如何用 Rust 类型状态（typestate）模式将内核 DMA 配置顺序编码进 API，是学习 Rust 安全抽象设计的优秀案例。
